## rc5 source remediation note

A read-only review of the working-tree changes confirms that `save_container.py` removes the `Cipher`/`BlowfishKey` classes, hardcoded cipher key, mix/unmix functions and encrypted-container read/write branches. It explicitly rejects the `EBNH` signature and keeps the supported unencrypted SYNC RDAT v9 parse/rebuild path. This is confirmation of source changes, not a runtime or new binary validation. OpenSSL can still be required for HTTPS through Python; removing the game-container cipher does not remove all runtime license obligations.

The UI source now states **NBA 2K27 / Windows x64 / quick play only** on the update, setup and maintenance/About surfaces. The missing-player UI reads the actual `last_sync.json` missing list, describes missing or ambiguous local records, and provides instructions to install an authorized compatible local roster update and then re-import its baseline. The added help does not implement a roster-pack downloader, distribute a pack, or claim to generate missing player records or artwork. The existing ESPN network data flow remains.

These changes reduce unnecessary capability and explain the data dependency. **They do not resolve the upstream implementation-provenance question, authorize modifying game data, establish ESPN data-access rights, or clear the old roster pack.** A user acknowledgement or local import is not a substitute for rights held by the relevant parties. The rc4 cipher and package observations in the detailed findings below are historical observations; the rc5 source remediation above supersedes their description of current cipher capability. Matching OpenSSL notices are being handled separately and were not assumed complete in this source review. No game, application UI, or test was run for this follow-up review.

## Findings that need a decision before public release

### 1. Referenced upstream code has no verified redistribution license

`save_container.py` acknowledges `u5ur/2K-Unpack-Save`. Its current repository root exposes `README.md` and `UnpackSave.py`, without a license file. The inspected upstream script and local implementation share the game-specific Blowfish key and bundle/node field layout; the implementations differ, including OpenSSL calls locally versus a Python cipher upstream. The local CRC salt was not located in that upstream script. These facts establish a provenance question, **not proof of copied protectable expression**. Constants and file-format methods alone do not establish copying.

`THIRD_PARTY_NOTICES.md` also acknowledges `discobisco/2k26-Editor` for earlier memory diagnostics. Its inspected root and README did not identify a license either. The public allowlist excludes the old memory-diagnostic tool, but the origin of any retained metadata or translated code still needs a record.

Action: identify the exact upstream revisions and any copied/adapted passages or metadata; obtain permission where required, or retain evidence that the shipped implementation was independently authored from format facts. A credit link alone does not grant redistribution permission. GitHub explains that public visibility without a license does not generally grant reproduction/derivative-work rights. The U.S. Copyright Office distinguishes methods from their expressive implementation. Sources: [unpacker repository](https://github.com/u5ur/2K-Unpack-Save), [inspected script](https://github.com/u5ur/2K-Unpack-Save/blob/main/UnpackSave.py), [editor repository](https://github.com/discobisco/2k26-Editor), [GitHub licensing guidance](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository), [Copyright Office Circular 33](https://www.copyright.gov/circs/circ33.pdf).

### 2. ESPN reachability is not an open-data license

`fetch_source.py` automatically fetches ESPN team rosters, depth charts and injury information; `schedule_notice.py` fetches fixtures. ESPN's own support page links to Disney's Terms of Use. Disney's U.S. terms, dated May 24, 2024 when inspected, include ESPN-branded products and restrict automated monitoring, copying and extraction without express written permission. The inspected project contains no provider permission or data-license document. Successful anonymous HTTP requests establish technical availability only.

Action: obtain permission or a provider license that covers this use, or use an appropriately licensed source through the existing configurable interface. Do not describe ESPN content as MIT, public domain, or officially authorized. Distributing only the client, limiting requests, deleting caches, attribution and using it without profit do not by themselves resolve the terms question. Do not implement access-control bypasses. Sources: [ESPN Terms support page](https://support.espn.com/hc/en-us/articles/360035445091-Terms-of-Use), [Disney Terms, sections 1 and 2.B](https://disneytermsofuse.com/english/).

### 3. Game modification and container decryption have separate risks

The utility edits a native roster payload and its manifest. `save_container.py` also includes an encrypted-container branch with a hardcoded game-specific key, although the supported SYNC RDAT workflow uses unencrypted nodes. There is no shipped game EXE patch or memory injector in the public allowlist.

Take-Two's inspected U.S. terms, last updated February 28, 2025, restrict modification, decryption, reverse engineering and certain unauthorized tools, subject to their stated exceptions and applicable law. Offline use and ownership of a game copy do not themselves prove permission. Whether a particular integrity mechanism is an effective access control, and whether an interoperability or other exception applies, requires legal analysis of the actual mechanism and jurisdiction; this audit makes no finding that a statutory violation has occurred. The unused encrypted-container capability deserves a necessity review before distribution.

Action: document the narrow NBA 2K27 Windows/SYNC format support and obtain advice on the applicable game agreement and reverse-engineering/access-control issues. Do not promise account safety, publisher approval or universal legality. Sources: [Take-Two Terms, sections 2.3 and 6.4](https://www.take2games.com/legal/en-US/), [U.S. Copyright Office section 1201 resources](https://www.copyright.gov/1201/).

### 4. The previously downloaded roster pack is not cleared for sharing

The historical download folder is no longer present at its supplied location. The retained source-package text `Sources/SYNC-20261002/pls/使用说明.txt` was inspected read-only: it contains a Steam/local installation instruction and promotional account information, without a copyright license or redistribution permission. The accompanying files were not redistributed or executed. A locally imported baseline and its integrity metadata remain; they record file identity and import time, not permission from a publisher or roster creator. No package author with verified rights, license or right to redistribute the earlier pack was established. Calling a folder an official roster update is not evidence of its origin or authorization.

Action: exclude that pack, game manifests, roster ZIPs, saves and download/extraction credentials from Git and release assets. Do not rehost or automate retrieval of the unverified share. Offer import of a compatible local native baseline that the user is authorized to use, explain the missing-player limitation, and allow an updated authorized baseline to be re-imported. An uploader's permission alone cannot necessarily authorize embedded publisher or player assets. Changing the delivery format to a patch/delta does not automatically clear those rights.

## Binary distribution notices

The inspected rc4 package contains Python, psutil, Tcl/Tk, OpenSSL DLLs, libffi, zlib and Microsoft runtime DLLs. Its `licenses` directory includes Python, psutil, PyInstaller and Tk notices. **The combined Python license already contains Tcl and Apache-2.0 license text**, so the absence of a separate Tcl filename is not a confirmed missing-license violation.

The OpenSSL DLL reports version **3.0.16** and its own copyright attribution; a read-only query of the build interpreter reports `OpenSSL 3.0.16 11 Feb 2025`. The combined license text and project notices do not identify OpenSSL by name. Add explicit component/version attribution and the [matching raw upstream license](https://raw.githubusercontent.com/openssl/openssl/openssl-3.0.16/LICENSE.txt); check whether any applicable upstream NOTICE or bundled-runtime terms also need preservation. Audit the remaining bundled DLLs against their actual build notices. This is a completeness concern, not a conclusion that every missing standalone notice filename violates a license.

PyInstaller's bootloader exception permits independently licensed applications, subject to dependency compliance; its presence does not make this entire app GPL. Sources: [PyInstaller license explanation](https://pyinstaller.org/en/stable/license.html), [OpenSSL licensing](https://openssl-library.org/source/license/index.html), [OpenSSL 3.0.16 license](https://github.com/openssl/openssl/blob/openssl-3.0.16/LICENSE.txt), [Tcl 8.6 license](https://github.com/tcltk/tcl/blob/core-8-6-branch/license.terms).

## Naming, artwork and player information

Use a distinct application name and identify NBA 2K27 as the supported compatibility target. Do not use league/team logos, publisher styling, player photos or game cover art as branding. A non-affiliation statement helps explain origin but does not grant trademark permission. A GitHub-name search is not a trademark clearance search. See [USPTO trademark guidance](https://www.uspto.gov/trademarks/basics/what-trademark).

Player names and factual status updates differ from copyrightable narratives, photographs and game assets. That distinction does not settle service contracts, database rights in all territories, or image/publicity rights. Do not automatically generate/distribute missing player faces or copy proprietary player records under the application's MIT label. The simple original geometric icon avoids third-party artwork provenance concerns; it is not a guarantee against every possible claim. See [Copyright Office explanation of protected expression](https://www.copyright.gov/what-is-copyright/).
