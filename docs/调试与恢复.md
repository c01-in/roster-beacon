# 调试与恢复

按本项目要求直接查真实日志、修改并交付，不新增、不编写、不运行 test。

## 状态与日志

在界面点击“打开日志目录”。

| 文件 | 用途 |
| --- | --- |
| app.log / app.previous.log | 最近操作与异常，超过 2 MiB 时轮换一份 |
| 启动状态.txt | 最近启动结果；success / success_with_missing / success_with_fallback 表示处理完成；回退详情见状态记录；failed_blocked_launch 表示更新失败后阻止启动 |
| last_sync.json | 最近成功写入的来源时间、30 队成员、出场顺序、伤病、缺少资料及清单校验值 |
| pending_sync.json | 提交暂存记录；正常结束清理，异常断电可能残留 |
| Backups/manifests | 原清单，文件名是 SHA256 |
| Baselines | 本机导入的原生基准与来源摘要，长期保留 |

Steam 的 game_launched=true 只代表发出了启动请求，不能当作已进入游戏或游戏内验收成功。

缓存目录的 espn_snapshot.json 在成功提交后删除，失败或预览时保留。网络请求在取得完整数据前失败时，可能只有异常日志而没有完整来源缓存。

## 实际操作入口

```powershell
Roster-Beacon-cli.exe --update-only
Roster-Beacon-cli.exe --diagnose
Roster-Beacon-cli.exe --import-baseline "D:\Path\To\Native\sync"
Roster-Beacon-cli.exe --restore
```

以上更新和恢复均保持游戏关闭；遇到正在运行的游戏会停止。源代码可用 python app_main.py 加同样的参数。--diagnose 输出不含本机绝对路径的摘要，适合附到 issue。

调试预览可在源码环境使用 python sync_nba.py --preview；失败后仍有缓存时可加 --cached。预览只生成临时文件，不提交清单。该命令应与其他操作错开使用。

## 常见问题

- **Steam 存档目录未找到**：先在游戏内生成本地数据，手动选择实际含原生 manifest 的 SYNC；不要随意选择另一个 Steam 账号。
- **本地 SYNC 被其他程序更新**：对照游戏更新、Steam Cloud 和其他 MOD；程序保留现场。确认当前名单正确后，通过设置重新导入它为基准。
- **布局与档案不符**：记录报错中的实际三张表位数，提供脱敏摘要。其他代际需要对应格式适配，不能取消校验强行写入。
- **缺少真实球员**：无需另装名单包。默认使用更新前本队原队员补位；整队零匹配或无法安全更新时保留该队原名单，相关转会暂缓。可选导入有权使用的新原生名单补齐记录。
- **伤病汇总漏人**：程序会采用球队名单中有效状态与日期，source_warnings 记录选择依据。没有可信状态时停止。
- **首发与比赛当天临时安排不同**：采用 ESPN 深度表和来源最新伤病，不保证赛前最后一刻发布的临时首发已包含。
- **赛程无法读取**：置顶提示并停止启动，保留成功同步结果和异常日志。可在配置里关闭赛程提醒。
- **权限不足或磁盘不足**：在设置里选择可写的数据/缓存目录；游戏 SYNC 仍需当前用户有写入权限。工具不会自行改 ACL 或提权。

## 恢复

游戏正常退出后，在“维护”点击恢复导入的基准。程序先备份当前清单，再引用已校验的原始名单。它保持个人生涯、赛季、王朝存档与游戏 EXE 原样。

若进程在提交时被强行终止或发生断电，先保留当前清单、pending_sync.json、last_sync.json 和相关 ZIP。多个文件没有断电级完整事务保证。无法确认状态时使用已导入的基准恢复，而不是删除保护记录绕过检查。
