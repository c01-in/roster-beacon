# 界面 review

## rc4：滚轮事件隔离（2026-11-02，洛杉矶）

用户复现了“球队下拉列表与设置页同时滚动”，rc3 的基础检查漏掉了这个交互组合。代码使用 bind_all 接收所有窗口的 MouseWheel；Tk 下拉列表自身的 bindtags 末尾也包含 all，因此列表滚动后还会执行页面滚动。

本次删除全局绑定，只给设置视口中已有的控件加入独立的事件标签。Tk 延迟创建的弹出列表、侧栏、日志和确认窗口不带此标签。关闭的下拉框不再被滚轮意外改值；设置表单内部的关闭下拉框仍允许滚动表单。语言切换保留表单滚动位置，并刷新未保存 SYNC 路径对应的清单选项。

已在打包的 rc4 便携程序上实际完成以下操作；人工交互阶段约 3 分钟（UTC 06:10:17–06:13:21）：

| 操作 | 实际结果 |
| --- | --- |
| 设置页空白/表单区域滚轮 | 表单正常滚动，固定保存按钮保持可见 |
| 展开球队列表，连续向上和向下滚动 | 可见球队从湖人附近移到凯尔特人附近，再移到森林狼附近；背景“比赛提醒”等字段位置保持不变 |
| Escape 关闭球队列表，再在关闭的球队框上滚动 | 球队保持湖人，表单正常滚动 |
| 展开启动方式后滚动，再取消 | 背景表单保持原位，值仍为 direct |
| 展开名单清单后滚动，再取消 | 背景表单保持原位，原清单保留 |
| 在关闭的语言框上滚动 | 语言和设置页位置保持原样 |
| 展开语言列表后滚动 | 背景设置页保持原位 |
| 切换 English，再切回跟随系统 | 表单保持原滚动位置，球队保持湖人，当前页面仍为设置 |

本轮保持原有游戏路径、基准、球队和启动方式，没有点击保存导入、实际同步或恢复；游戏保持关闭。未新增或运行自动化测试。Steam 账号选择框共用相同的下拉实现，本轮没有进入其实际账号选择流程；高精度物理滚轮的小幅增量也没有用对应硬件实测。本记录不扩张为所有 UI 场景均已通过。

## rc3：布局修订

## 对照依据与范围

对照 Microsoft WinUI Gallery 的 NavigationView 示例和 Fluent 字体规范，采用固定导航、单个页面名称、靠近操作对象的按钮与分组表单。没有复制它们的图标、图片或商标。

- https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/navigationview
- https://fluent2.microsoft.design/typography
- https://learn.microsoft.com/en-us/windows/win32/hidpi/setting-the-default-dpi-awareness-for-a-process

rc2 的检查只覆盖了打开界面和语言切换，覆盖不足。用户指出的大横幅、宣传文案、页签尺寸变化和文字清晰度问题属实；本轮按这些具体问题修改。

## 修改依据

| 问题 | rc3 实现 |
| --- | --- |
| 大标题、副标题及图形横幅占据工作区 | 删除横幅、宣传文案和对应绘图代码；只保留功能页面名称和侧栏小图标 |
| 选中页签高度和位置变化 | 删除 ttk Notebook；固定侧栏行高 40 个逻辑像素，选中和悬停只改颜色 |
| 字号混用、输入文字偏小 | 中文 Microsoft YaHei UI / 英文 Segoe UI；正文及输入控件 11 pt，页面名称和统计值 16 pt |
| 高缩放下文字位图放大 | 打包 manifest 声明 system DPI aware；源码入口在创建 Tk 前设置相同模式；布局尺寸按 Tk DPI 缩放 |
| 默认白色控件状态 | 定义按钮、输入框、下拉框、滚动条及复选框样式，按钮焦点用固定宽度边框表达 |
| 选中状态改变控件尺寸 | 所有状态共用布局、字体、内边距和边框宽度；复选框使用相同尺寸的选中/未选中图形 |
| 设置操作滚出窗口 | 保存按钮固定在表单外底部；表单可滚动，长描述随内容宽度换行 |

## 实际操作记录（2026-11-02，洛杉矶）

在打包后的便携程序中实际查看中文首页，点击各侧栏入口，滚动设置表单，切换复选框选中状态，通过下拉菜单切换英文，查看英文设置与维护页，打开恢复确认并点击取消，再将窗口缩至约 900 个逻辑像素宽查看英文首页和维护内容换行。

这轮操作确认导航行的位置和尺寸稳定、按钮文字可见、保存操作固定可见、确认和取消使用一致高度的深色控件。实际查看又发现输入控件采用较小默认字体、复选框文字间距不足和未选中边框过暗，已针对这些问题修正后重新打包。

没有启动游戏、点击实际同步或执行恢复；取消确认保留名单。未新增或运行自动化测试。当前采用系统 DPI 感知，本轮没有改变用户显示设置，也没有验证不同 DPI 的多显示器间实时切换；该模式不等同于 Per-Monitor V2 支持。尚未实际触发长时间同步，因此运行中的禁用状态只完成样式实现，不能记为长任务实测通过。
