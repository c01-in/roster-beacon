# 配置参考

日常只需选择游戏、确认自动找到的名单、选择提醒球队后保存。内部目录和版本配置自动管理，下面这些字段收在默认折叠的高级设置。“维护 → 打开高级配置”可编辑其余选项。配置文件本身不含密码或 Steam 登录凭据；工具不请求这些凭据。

| 键 | 用途 |
| --- | --- |
| language | auto：跟随 Windows 显示语言（中文→中文，其他→英文）；zh-CN 或 en-US：固定语言；GUI 左下角可切换 |
| game_executable | 本机游戏 EXE 绝对路径；同时用于运行状态识别 |
| launch_mode | steam 或 direct；Steam 通过原生协议启动 |
| steam_app_id | 来自本机 appmanifest 的 App ID，Steam 启动必填 |
| sync_directory | 游戏实际读取的 SYNC 目录，多个 Steam 账号应分别选择 |
| manifest_name | 该目录中引用 roster_path 的原生 manifest_*.bin |
| roster_path | 清单内逻辑路径，默认 roster/roster.iff |
| data_directory | 独立的基准、备份、状态和日志目录；不同安装/存档位置使用不同数据目录 |
| baseline_directory | 导入后指向以清单 SHA256 命名的不可变基准目录 |
| cache_directory | 可重建来源缓存与临时构建目录；成功后自动清理来源 |
| compatibility_profile | 内置 nba2k27-rdat-v9 或外部 JSON 档案绝对路径 |
| team_map_file | 可选的本机球队映射 JSON；留空使用内置 30 队映射 |
| injury_types_file | 可选伤病枚举 JSON；留空使用内置版本 |
| allow_missing_players | true：缺员时原队员补位或整队保留并提示；false：缺少任何人就停止 |
| scope | 当前为 NBA_ALL_30_TEAMS |
| show_schedule | 是否在启动前显示置顶赛程确认 |
| schedule_team_id | ESPN 球队 ID，默认 13（湖人）；GUI 可选择 30 队 |
| api_base | HTTPS 数据接口根路径，默认 ESPN NBA 公共接口 |
| season_year | 0 表示按当前 UTC 日期及 7 月分界计算赛季结束年，也可明确指定年份 |
| request_timeout | 网络请求超时秒数，1–120，默认 30 |
| network_workers | 网络并行请求数，1–12，默认 6 |

路径不固定于安装盘、Windows 用户名、Steam 账号或某个发行渠道。便携版默认仍使用独立配置目录，可通过 NBA_ROSTER_SYNC_CONFIG 指定配置文件。

推荐把 data_directory 放在长期保留的位置，把 cache_directory 放在可删除的缓存位置。基准和备份不能放进临时清理目录。

语言识别使用 Windows 显示语言 API，而非时区、地区格式或截图文字识别。`NBA_ROSTER_SYNC_LANGUAGE` 环境变量可临时覆盖语言，命令行 `--language auto|zh-CN|en-US` 优先于环境变量；GUI 手动切换后保存到当前配置并清除本进程临时覆盖。文件选择器属于 Windows 原生界面，其系统按钮跟随 Windows 语言；工具自己的页面、按钮、进度、错误和赛程窗口跟随工具语言。

## 首次使用确认

确认独立保存在配置文件旁的 `<配置文件名>.usage-consent.json`，不与路径设置一起覆盖。记录说明版本、接口根路径、兼容档案和确认时间；改变来源、兼容档案或说明版本后重新询问。通过“维护 → 关于 → 撤回首次确认”清除。查看说明和诊断本身不访问数据源，恢复基准及使用缓存不获取数据。确认记录不随源码、安装包或诊断摘要分发。

## 自动配置与恢复备份

选择 EXE 后与查找 Steam 使用同一探测入口。校验候选的原生清单、ZIP 和三张名单表布局；结果不明确时展示候选及实际保存时间，不按时间擅自覆盖。未找到时提示游戏先生成数据，绝不创建空 SYNC 目录。

工具备份和缓存默认按游戏/存档标识分别管理；已有配置的目录保持原样。普通保存保留现有 baseline_directory；更换安装、存档、存储或适配档案，或主动重新导入时才建立新的恢复备份。其他本机导入来源是高级可选项，与自动生成的恢复备份位置分开。
